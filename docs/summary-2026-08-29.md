# Market Analysis Tool — Project Summary

A layperson-friendly overview of what this project is, what it does, what has
been built, and what has been fixed. Written in plain English so anyone can
follow it. Technical details live in `AGENTS.md`.

---

## What is this project?

It is a **small website that runs on your own computer** and helps you keep
tabs on the stock market. Think of it as a personalized market dashboard that
pulls together the kind of information a serious market watcher would want,
all on one page.

The app was inspired by four older "frozen" planning files
(`ai_market_cycle_diagram_v4.html`, `ai_market_sentiment_gauge.html`,
`ai_market_positioning.html`, `ai_thesis_timeline.html`) that describe the
analysis framework being used. Those files are kept as-is and never modified.

Everything the dashboard shows is fetched live from free, public data sources
(no API keys, no paid subscriptions, no cloud). All of the math is done on
your machine.

---

## What does the dashboard show?

The page is split into "cards." Each card answers one question:

| Card | What it answers |
|---|---|
| **Risk banner** (top) | "Is the market one-sided right now?" (its most dangerous state) — flashes GREEN, YELLOW, or RED with the specific evidence and the conditions that would flip the color. |
| **Fragility flags** | The specific signals that show "everyone's leaning the same way" — historically when trouble starts. |
| **Macro regime** | What *type* of market regime we're in (broadening, contraction, inflationary, etc.) using six cross-asset signals. |
| **Indicators** | How wide the rally is, whether the S&P trend is healthy, how jumpy volatility is, what VIX is doing. |
| **Indices & Rates** | S&P 500, Nasdaq, Dow, Russell, VIX, Treasury yields, oil, gold. |
| **Breadth charts** | What percent of sectors/indices sit above their 50-day moving average — a measure of how broad the rally is. |
| **Bottleneck** | Where in the supply chain are there scarce, monopoly-style choke points (semiconductors, photonics, rare earths, etc.). |
| **AI capex-cycle gauge** | Are we in an AI infrastructure boom, a top, or a fade? Combines AI-stock momentum, AI-news sentiment, and valuation stretch. |
| **13F superinvestors** | What the famous investors (Berkshire, Bridgewater, etc.) have been buying/selling, from SEC filings. |
| **Earnings calendar** | Upcoming earnings for the mega-cap universe, with a local rule-based "AI" recommendation. |
| **Events timeline** | The curated, hand-tagged timeline of major market events in 2026 + only the most important (High/Critical) live news. |

A small "coverage" badge appears on any card if some of its inputs are missing
— so you know when something is degraded instead of just blank.

## What has been built?

The project shipped its **initial commit on 2026-08-22** and has had **60
commits** over six days (latest on 2026-08-27). Work happened in three phases.

### Phase 1 — Fix the bugs (2026-08-22, branch `fix/review-errors`)

A full code review turned up ~30 issues: real bugs, fragile designs, and
improvement ideas. Three specialist agents worked in parallel to fix the
actual bugs (17 commits), each running the full test suite before every commit.

**Result: 17 bugs fixed, zero regressions, 9/9 tests passing.**

### Phase 2 — Build the improvements (2026-08-22, branch `improvements/review-2026-08-22`)

Eight approved improvements from the review landed: shared math library,
centralized config, faster bottleneck card, per-card coverage badges, per-card
timestamps, safer scheduled tasks, frontend module split, and a big new test
suite.

**Result: 16 commits, tests went from 9 to 61, all passing in ~1 second.**

### Phase 3 — Resolve the parked decisions (2026-08-23, branch `parked/review-2026-08-23`)

Nine items that needed user judgment got decided and implemented one-by-one:
semiconductor double-count in breadth, missing-data neutrality in AI gauge,
regime-report expiration, division-score removal, fragility flag side-tags,
cross-process locking, auth posture, event-delete precedence, and removing the
dead Stooq data fallback.

### Phase 4 — Harden the news section (2026-08-26 → 2026-08-27)

The news/events section was redesigned for cross-device sync via Git (the
timeline now lives in a plain JSON file), with a tag-editor popover, AI-tag
toggle, modal delete confirmation, and a live RSS ingest path. Test coverage
for previously-untested modules was backfilled in one big drop.

**Result: 250 tests passing (up from 9), 0 failing.**

## What has been fixed?

### Numbers you see are trustworthy now

| Bug | Why it mattered |
|---|---|
| The "valuation stretch" signal could never fire | Compared a list against its own top quartile — mathematically almost impossible. Risk signal #9 and the AI gauge's −15 penalty were dead code. Now uses a simple absolute rule (median forward PE ≥ 30×). |
| "Median" wasn't the median | For even-sized lists it picked the upper-middle value, slightly skewing PE readings. Now uses real statistical median. |
| RED alert could never trigger on bad-data days | Demanded "5 bullish signals" even when only 3 had data — silent exactly when it mattered most. Gates now scale with available signals. |
| Crashes on impossible prices | A zero/negative price would crash log-math in correlation and volatility code. Now treated as missing. |
| Confidence scores understated | A hand-typed constant said weights total 15; they actually total 14. Total is now computed from the table. |
| Crash risk on malformed dates | Non-text dates raised an uncaught error in the synthesis engine. Now handled safely. |
| Missing AI-gauge data read as "calm" | Missing cohort data was silently treated as 0% / 50%. Now shows "unknown / insufficient data." |
| Semiconductors double-counted in breadth | SMH and SOXX voted twice in every "% above 50-day MA" figure. Dropped SOXX. |
| Risk division score always read 1.0 | Showed "maximally divided / healthy" when zero signals existed — exactly backwards. Removed. |
| Fragility flags mixed both sides | Distress-side breakage could help satisfy a "consensus optimism" gate. Flags now tagged `optimism` or `distress`; gate counts optimism-side only. |

### Outages no longer poison the dashboard

| Bug | Why it mattered |
|---|---|
| Failed Yahoo downloads cached as real | Empty results were stored and served for 24 hours — breadth/risk went blank and looked like "no signal." Failed fetches are never cached now. |
| An EDGAR outage wiped 13F data for 20 days | A failed rebuild overwrote the good cached snapshot with an empty one. Last good snapshot is kept on failure. |
| News fetch could hang forever | No timeout on the RSS download; undated articles got a fabricated "now" timestamp. Now: 15-second timeout, undated entries dropped. |
| Database housekeeping ran on every operation | Schema checks executed on nearly every read/write. Init runs once per process; JSON writes are atomic. |
| Concurrent page loads triggered duplicate refreshes | Opening the dashboard in two tabs launched two ~1-minute refreshes. A cross-process lock ensures one at a time. |
| Regime detector crashes escaped | Missing files or OS errors could kill a refresh. Now handled — serve cached report. |
| EDGAR fetch blocked by TLS mismatch | `www.sec.gov` started 403'ing plain-Python. Now uses `curl_cffi` browser-TLS impersonation. |

### Input is now checked

| Bug | Why it mattered |
|---|---|
| Deleting an event with no arguments "succeeded" | Returned 200 while doing nothing. Now 400. |
| Any garbage string could be added as a ticker | Invalid symbols persisted forever and could write outside the cache folder. Now validated with a human-readable rejection reason; filenames sanitized. |
| Compound deletes silent | `DELETE?link=X&source=Y` deleted by link and ignored source. Now 400 — compound deletes must be two deliberate calls. |
| DNS rebinding possible | Any Host header was accepted. Now a Host-header allowlist middleware blocks foreign hosts (only `127.0.0.1`, `localhost`, `[::1]`). |

### The dashboard no longer lies after refreshes

| Bug | Why it mattered |
|---|---|
| `javascript:` links from feeds could execute | Stored XSS — only http/https links become clickable now. |
| Older data overwrote newer data | Rapid refreshes raced each other. Generation tokens now discard stale responses; HTTP errors are detected; failed actions show inline messages. |
| Zero prices dropped, NaN kept | Bottleneck momentum filters discarded valid 0.0 closes. Now keeps zeros, drops NaN. |
| AI tag came back after manual removal | Updates re-applied the auto-tag. Now: insert-only; updates preserve user tags. |
| Tag popover vanished in same click | Document-level click handler fired on the click that just opened it. Now stashed while the source pill is being clicked. |
| Tag popover CSS conflict | `[hidden]` lost to `.tag-add-form`. Now an explicit `[hidden] { display: none !important }` guard. |
| News wipe on merge conflict | Two-step recovery added. |

### Polish and observability

- **Math consolidated.** Same calculations were hand-copied in four files; now one canonical home in `app/indicators.py`.
- **Settings centralized.** All tuning numbers moved to `app/config.py` — no more hunting through code.
- **Bottleneck card faster.** Proxies fetched in one bulk batch instead of one-by-one.
- **Per-card coverage badges.** Cards show `7/9`-style count when something is missing; healthy dashboard is unchanged.
- **Per-card timestamps.** Each section shows its own "As of HH:MM" — honest about mixed-age data.
- **Frontend organized.** The 1,366-line `app.js` monolith became 8 small modules; labels now come from the backend (`GET /api/meta`).
- **Scheduled tasks safer.** Daily log rotation (keeps 30 days); 4-hour execution limit (was 1); installs are overwrite-safe.
- **Wake-from-sleep.** Scheduled tasks can wake the laptop so triggers fire on time.
- **News sync across devices.** The events timeline is a plain JSON file in Git; everything else stays local so two devices running refresh don't silently diverge the timeline.

## How to run it

```bash
python -m pip install -r requirements.txt
python run.py              # open http://127.0.0.1:8000
python run.py --refresh    # one full refresh and exit
python -m pytest tests/    # run the 250-test suite
```
