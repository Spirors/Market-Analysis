# Audit pass — Market Analysis Tool (2026-08-26)

A plain-language write-up of the code review done today.

## What this app is

A small dashboard that lives on your computer. It pulls free market data
(yfinance, public RSS feeds, SEC filings) and shows you a single page with
lots of cards: trend, risk, news timeline, earnings calendar, superinvestor
13F holdings, an AI capex-cycle gauge, and so on. It also does its own math
to score market "regime" and to flag when sentiment is getting one-sided
(which historically is when risk shows up). Everything runs locally, no
cloud, no API keys.

## What I did today

I went through every visible card on the dashboard, every Python module
behind it, and the existing tests. I checked that each card is wired to
something real (an API endpoint that returns real data, a renderer that
puts that data on screen). I looked for anything broken or missing.
Then I added new tests where the gaps were big.

## What I found

### Things working well

- **Every card has a real renderer.** No dead UI, no orphan renderers.
- **All 14 documented API routes exist.** Nothing was promised in AGENTS.md
  that the backend doesn't actually serve.
- **Cross-device sync model is sound.** Events live in a Git-tracked JSON
  file; market data and analysis logs stay local. This is intentional and
  documented.
- **The risk engine's logic is well-tested.** 13 dedicated tests cover the
  GREEN/YELLOW/RED gates, fragility side-tags, valuation stretch, edge
  cases.
- **The events store has good test coverage** — atomic writes, dedupe by
  link, dedupe across sources, tag add/remove, AI auto-tag-on-insert-only.
- **Per-card refresh works** with generation tokens, so a slow refresh
  can't overwrite a faster one with stale data.

### One pre-existing bug

`tests/test_api_contract.py::test_list_events_endpoint_respects_limit`
crashes on setup. It still references `config.DB_PATH`, which doesn't exist
anymore — the events store moved from a single SQLite file (`news.db`) to
a JSON file (`events.json`) earlier. The test needs to point at
`config.EVENTS_PATH` instead. **Fix is in progress.**

### Test coverage gaps I closed

Added five new test files (and one fix):

| File | What it locks down |
|---|---|
| `tests/test_indicators.py` | breadth math, ROC window math, VIX signal bands, trend classification, realized vol |
| `tests/test_news_analyze.py` | the keyword heuristics that classify a headline (macro/micro, region, direction, impact tier) |
| `tests/test_earnings_rec.py` | the local "AI-style" rec signal logic and the helpers that format prices/market-cap |
| `tests/test_service_coverage.py` | the per-section "n/m" coverage counters that power the small badges on each card |
| `tests/test_regime_stale.py` | the regime report's stale-flag fallback when detection hasn't run recently |

### Things I noticed but did not change

- **`app/thirteenf.py` has no isolated tests.** It hits SEC EDGAR directly
  (with curl_cffi browser-TLS impersonation), so tests would either need
  to mock the network layer or record/replay HTTP. The API contract tests
  exercise it indirectly. Not worth the test scaffolding today.
- **`app/scheduler.py` has no tests.** It's a thin wrapper around
  `schtasks.exe`; testing it would mean mocking Windows. The XML it builds
  is small and mostly template strings.
- **`app/run.py` CLI is uncovered.** Same reasoning: would need a process
  harness. The CLI flags are stable and well-used.
- **One tiny visual quirk in Earnings:** the "Sector" column is right-
  aligned because it inherits `num: true` from the column descriptor in
  `earnings.js`. Harmless. Could be fixed by removing `num: true` from the
  `sector` entry. Left alone — not worth a behavior change.

## What this means in practice

- The app is in good shape. The risk engine, the synthesis (analysis.py),
  the events timeline, and the cache layer all behave correctly under tests.
- The biggest functional risk before today was untested math. The new
  tests pin down the indicator formulas (breadth %, ROC, realized vol,
  VIX regime bands) so any future tweak will fail loudly.
- The remaining gaps are network- or platform-specific and were
  intentionally scoped out.

## How to run the test suite

```bash
python -m pytest tests/ -v
```

You should see **no failures, no errors** after the fix lands. The suite
runs in a couple of seconds — no network, no live data.
